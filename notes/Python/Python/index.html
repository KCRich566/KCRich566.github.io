Python for Software Design

Python favors readable code, small modules, and protocols based on behavior. Its flexibility is powerful, but clear boundaries are still needed as a system grows.

Modules and packages

Keep a module focused on one concept. Expose a small public surface from packages and keep implementation details private by convention. Avoid circular imports by making dependencies point toward stable lower-level modules.

Objects and protocols

Python uses duck typing: an object is useful when it provides the operations a caller needs. typing.Protocol lets that structural contract be documented and checked without requiring inheritance.

Exceptions and boundaries

Raise exceptions for exceptional failures and translate infrastructure errors at a boundary. Callers should receive errors that make sense for their layer rather than raw database or network details.

Testing

Prefer pure functions for transformations and inject clocks, clients, or file systems at the edge. This keeps most tests fast while leaving a smaller number of integration tests for real boundaries.
