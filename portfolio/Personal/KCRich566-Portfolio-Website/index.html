KCRich566 Portfolio Website

Direction

This website is designed as a professional platform rather than a generic landing page. Portfolio work is the primary surface; Notes explain the thinking behind systems and Lab provides small, interactive demonstrations.

The content is organized around three questions:

  • What have I built?
  • How do I think about engineering problems?
  • What can I demonstrate directly in a browser?

Information architecture

Home
├── About: background, capabilities, experience
├── Portfolio: company and personal case studies
├── Notes: long-form technical explanations
└── Lab: browser-only experiments and tools

Technical stack

  • Next.js App Router
  • React and TypeScript
  • Tailwind CSS with global CSS for content surfaces
  • MDX compiled with next-mdx-remote
  • gray-matter for frontmatter metadata
  • rehype-pretty-code and Shiki for code highlighting
  • Static generation for GitHub Pages deployment

Content system

Markdown and MDX files are the source of truth. Frontmatter supplies titles, descriptions, dates, tags, and categories. Server-side loaders scan the content directories and generate static routes.

This keeps writing separate from page layout while preserving a predictable build. A new portfolio case study is a content file, not a database migration.

Design concepts

The visual language uses restrained typography, warm paper-like surfaces, dark technical panels, and clear spacing. Case studies favor context, decisions, diagrams, and outcomes over decorative mockups when the original product cannot be publicly demonstrated.

The Lab is intentionally browser-only. File operations use local browser APIs so a visitor can experiment without uploading private images or notes.

Trade-offs

Static generation makes the site fast, portable, and suitable for GitHub Pages, but it means content changes require a new deployment. The architecture accepts that trade-off because this site is a curated professional archive rather than a real-time application.

Outcome

The result is a small publishing system tailored to engineering work: public case studies can remain generalized, technical reasoning has a home, and interactive ideas can be demonstrated without a backend.
