Teledyne DALSA Camera Library Integration

An AOI camera integration project that adds Teledyne DALSA support while preserving a vendor-independent camera abstraction for the application layer.

01. 專案背景

因應新的 Teledyne DALSA Camera 導入，既有 Camera Library Framework 需要新增對應的 Camera Support。

如果直接讓 AOI Application 使用新的 Camera SDK，會使上層 Application 開始依賴特定 Camera Vendor 的 API，增加後續 Camera 替換與 Software Maintenance 的成本。

因此，本專案的主要工程問題為：

如何將第三方 Camera SDK 整合至既有 Camera Library Framework，同時維持原有 Camera Abstraction，讓上層 AOI Application 不需要直接處理 Vendor-specific Camera API？

我主要負責研究 Teledyne DALSA Camera SDK，並將其 Camera Control 與 Image Acquisition 能力整合至既有 Camera Library。

02. 專案目標與系統架構

2.1 專案目標

本專案的主要目標，是在既有 Camera Library Architecture 中加入 Teledyne DALSA Camera Support。

主要包含：

  • 研究 Teledyne DALSA Camera SDK
  • 建立 Camera Initialization 與 Device Detection
  • 整合 Camera Configuration
  • 整合 Image Acquisition
  • 整合 Camera Parameter Control
  • 將 Vendor-specific API 封裝於 Camera Library
  • 維持既有 Camera Library Interface
  • 讓 AOI Application 能夠使用新的 Camera

核心概念為：

Camera SDK → Camera Integration Layer → Existing Camera Library → AOI Application

2.2 System Architecture

整體架構將 Third-Party Camera SDK 限制在 Camera Integration Layer，由該 Layer 負責處理 Vendor-specific API。

既有 Camera Library 對上層提供一致的 Camera Interface，使 AOI Application 不需要直接操作 Teledyne DALSA SDK。

在此架構下，Camera Control 與 AOI Inspection Logic 維持分離，而新的 Camera 也可以透過既有 Library Architecture 納入 AOI System。

03. 我的設計與實作

3.1 Third-Party SDK Analysis

我首先研究 Teledyne DALSA Camera SDK，了解其 Camera Device Discovery、Initialization、Configuration、Image Acquisition 與 Parameter Control 等功能。

研究重點不只是熟悉 SDK API，而是確認 Vendor SDK 所提供的能力如何對應至既有 Camera Library Framework。

因此，我將 Vendor SDK 的功能與既有 Camera Interface 進行 Mapping，確認各項 Camera Capability 的整合方式。

3.2 Camera Adapter / Integration

在既有 Camera Library Framework 中加入 Teledyne DALSA Camera Support，並將 Vendor-specific API 封裝於 Integration Layer。

由 Integration Layer 負責處理：

Existing Camera Interface → Teledyne DALSA Integration → Camera SDK

上層 Camera Library 則維持既有的抽象介面，使 AOI Application 不需要直接依賴 Teledyne DALSA SDK。

3.3 Camera Initialization & Device Detection

整合 Camera Initialization 與 Device Detection Flow，使 Camera 可以透過既有 Camera Library 完成初始化與連線。

整體流程包含：

Application → Camera Library → Camera Initialization → Device Detection → Camera Ready

透過統一的 Library Interface 管理 Camera 的初始化與連線流程，避免上層 Application 直接處理 Vendor SDK 的初始化細節。

3.4 Camera Configuration

將 Teledyne DALSA Camera 所需的 Configuration 與 Parameter Control 能力整合至既有 Camera Library。

上層 AOI Application 可以透過既有 Camera Interface 使用 Camera Configuration，而不需要直接處理 Vendor-specific API。

透過這種方式，將：

Camera Control Logic

與

AOI Inspection Logic

分離，讓 Camera Integration 不會直接侵入上層 Inspection Application。

3.5 Image Acquisition

整合 Teledyne DALSA Camera 的 Image Acquisition Flow。

Camera 取得影像後，由 Camera Integration Layer 處理 Vendor SDK 相關操作，再透過既有 Camera Library 提供一致的 Image Acquisition Interface 給 AOI Application。

因此，AOI Application 可以維持原有的影像取得方式，而新的 Camera SDK 則被封裝於底層 Integration Layer。

3.6 Existing Architecture Integration

本專案的重要設計考量，是維持既有 Camera Library Architecture。

如果直接將 Teledyne DALSA SDK API 暴露給 AOI Application，雖然可以完成 Camera Integration，但會增加 Application Layer 對特定 Camera Vendor 的依賴。

因此，我將 Vendor-specific implementation 限制在 Camera Library 的 Integration Layer，使上層 Application 維持既有 Interface。

這讓 Camera Vendor 的差異被封裝在 Library Layer，而 AOI Application 可以繼續使用一致的 Camera Abstraction。

3.7 Engineering Problem Handling

本專案的主要工程問題可以分為三個階段。

第一階段是 Vendor SDK Analysis，確認第三方 SDK 提供的 Camera Control 與 Image Acquisition 能力。

第二階段是 Architecture Mapping，將 Vendor-specific API 與既有 Camera Library Interface 建立對應。

第三階段是 Application Integration，確認新 Camera 導入後，上層 AOI Application 仍能透過既有 Camera Library 正常使用 Camera。

因此，整體設計思考並不是單純「加入新的 Camera SDK」，而是：

New Camera Requirement → SDK Analysis → Interface Mapping → Integration → Existing Camera Library → AOI Application

透過這種方式完成第三方硬體 SDK 與既有 Software Architecture 之間的整合。

04. 成果

完成 Teledyne DALSA Camera SDK 與既有 Camera Library Framework 的整合，使 AOI System 能夠支援新的 Camera。

透過 Camera Integration Layer 封裝 Vendor-specific API，使 AOI Application 不需要直接依賴特定 Camera SDK，同時維持既有 Camera Abstraction。

完成一致的：

Initialization → Device Detection → Configuration → Image Acquisition

Camera Workflow，讓新 Camera 可以透過既有 Camera Library 整合至 AOI Application。

本專案將 Third-Party SDK Integration、Hardware Abstraction、Library Development 與 AOI System Integration 串接起來，在維持既有 Software Architecture 的前提下完成新型 Camera 的導入。
