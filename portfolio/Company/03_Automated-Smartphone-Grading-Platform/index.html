01. 產品背景

在 Smartphone Refurbishment 流程中，Cosmetic Grading 需要根據 Inspection System 產生的檢測結果，判斷裝置的外觀狀態與對應 Grade。

傳統的 Cosmetic Grading 高度依賴人工判斷，不同 Operator 可能產生不同的判定結果；同時，不同 Customer 對於 Defect Type、Defect Size、Defect Location 與 Grade 定義，也可能具有不同要求。

因此，需要將既有 Inspection System 的檢測結果，轉換成一套可配置、可重複執行、可追溯的自動化 Grading Decision。

本產品的核心並非開發 Inspection Equipment，而是從既有 Inspection System 的輸出開始，建立後續的 Software Platform，將 Inspection Result、Device Identification、Grading、Production Traceability、Cloud Integration 與 Customer Integration 串接成完整的 Production Workflow。

產品由初期 MVP 開始，逐步加入 Machine Integration、Configurable Grading、AI-based Device Identification、Cloud Integration、Customer API 與 Production Deployment，最終形成完整的 Automated Smartphone Grading Platform。

02. 產品定義

產品定位為一套連接 Inspection System 與 Production System 的 Automated Smartphone Grading Platform。

系統接收 Inspection Equipment 產生的 Inspection Result，根據 Device Model 與 Grading Rules 進行 Grade Calculation，產生 Grade Decision 與 Downgrade Reason，並建立 Production Record。

核心功能

平台主要涵蓋：

  • Inspection Result Processing
  • Machine Integration
  • Device Identification
  • Model-Specific Configuration
  • Configurable Grading Engine
  • Production Traceability
  • Cloud Integration
  • Customer API Integration
  • Production Reporting
  • Production Deployment

核心概念是將原本分散於 Inspection Result、人工判斷與 Customer Requirement 中的資訊，轉換成一致且可追蹤的 Software Decision Process。

03. 系統設計

3.1 Platform Architecture

系統採用分層設計，將 Machine Integration、Application Workflow、AI Inference、Grading Decision、Production Traceability 與 External Integration 分離。

Inspection Equipment 產生 Inspection Result 後，由 Machine Integration Layer 接收設備事件與檢測資料，再交由 Application Workflow 進行後續處理。

Application Workflow 負責管理 Device Context、Inspection Result 與後續 Decision Process，並串接 Device Identification、Model Configuration 與 Grading Engine。

完成 Grade Decision 後，再將結果進入 Production Traceability、Cloud Integration 與 Customer System。

透過分層設計，使 Machine Communication、Business Logic、AI Service 與 External System Integration 能夠保持相對獨立，降低後續產品演進時的耦合程度。

3.2 Configurable Grading Engine

Grading Engine 是平台的核心 Decision Logic。

初期 Grading Logic 直接存在 Application Code 中。當 Customer Grading Requirement 改變時，需要修改程式並重新部署。

因此，我將 Grading Rule 與 Application Logic 分離，建立 Configurable Grading Engine，並使用 XML 定義 Grading Rules。

Rule 可以根據不同 Inspection Result 進行組合，例如：

  • Defect Type
  • Defect Count
  • Defect Size
  • Defect Area
  • Defect Location
  • Region-Based Rules
  • Critical Defect Override
  • AND / OR Conditions

透過這種設計，Grading Decision 不再完全依賴 Hard-coded Logic，而是由 Inspection Result、Device Model 與 Grading Configuration 共同決定。

這讓 Grading Rule 可以獨立於 Application Code 演進，也讓不同 Customer 的 Grading Requirement 更容易管理。

3.3 Grading Decision Design

在設計 Grading Engine 時，也考慮過 Machine Learning 與 Decision Tree 等方式。

最終採用 Rule-Based Grading Engine，主要考量 Production Grading 不只需要產生結果，也需要能夠說明判定依據。

因此 Decision Logic 需要具備：

  • Transparent
  • Traceable
  • Auditable
  • Configurable
  • Customer-specific

等特性。

透過 Rule-Based Design，可以讓 Grade Decision 與其判定條件保持明確關聯，便於 Production Troubleshooting、Rule Tuning 與 Customer Acceptance。

3.4 AI Device Identification

不同 Smartphone Model 可能需要不同的 Inspection Configuration 與 Grading Rules。

原始流程需要 Operator 手動選擇 Device Model，因此我加入 AI-based Device Identification。

既有 Inspection Workflow 已經能取得 Smartphone Image，因此直接利用既有 Image Stream，不需要額外增加影像硬體。

AI Model 使用 Xception 進行 Image Classification，將影像轉換為 Device Model Identification 結果，再提供給主要 Application 選擇對應的 Model-Specific Configuration。

AI Model 透過獨立的 Inference Service 提供識別能力，主要 Application 透過 HTTP Interface 與 Inference Service 溝通。

將 AI Model 與主要 Application 分離，可以降低模型更新對主系統的影響。

3.5 Production Traceability

為了讓每次 Production Transaction 都能追蹤，我將 Device、Inspection、Grade 與 Production Information 串接在同一個 Workflow。

Production Record 可包含：

  • Device Information
  • Grade
  • Downgrade Reason
  • Machine Information
  • Inspection Information
  • Software / Rule Version
  • Production Transaction Information

因此系統不只是產生 Grade，也建立從 Device、Inspection、Decision 到 Production 的完整 Traceability。

3.6 Cloud & Customer Integration

平台進一步整合 Cloud Service，將 Inspection 與 Production Data 進行集中管理。

Cloud Integration 支援：

  • Production Data Storage
  • Inspection Data Storage
  • Reporting
  • KPI Tracking
  • Yield Analysis
  • Production Monitoring
  • Transaction Tracking
  • Cross-Site Operational Visibility

另外透過 Customer API 與外部 Production System 整合，使 Grading Result 能夠進入既有 Customer Workflow。

04. 產品開發

4.1 MVP Development

產品採用 Incremental Development，先建立最小可運作的 End-to-End Workflow，再逐步加入 Production Requirement。

初期 MVP 先完成基本流程：

Inspection Result → Basic Grading Logic → Grade Result

先驗證 Inspection Result 能否正確進入 Application，並完成基本 Grade Calculation。

4.2 Machine Integration

完成 MVP 後，進一步建立與 Inspection Equipment 的 Machine Communication。

主要處理：

  • Persistent Socket Communication
  • Machine Event
  • Inspection Completion
  • Inspection Result Processing
  • Application Workflow Trigger

系統不以固定時間等待，而是根據 Machine Event 與 Inspection Result 驅動後續 Workflow，使 Application Flow 能夠與實際設備狀態同步。

4.3 Grading Engine Development

初期 Grading Logic 為 Application 內的固定邏輯。

隨著 Customer Requirement 增加，逐步將 Grading Logic 抽離成 Configurable Rule Engine。

透過 Rule Abstraction 與 XML Configuration，使 Grading Rule 可以獨立於核心 Application Logic 進行調整。

這項設計也讓後續 Customer-specific Requirement 能夠透過 Configuration 擴充，而不需要頻繁修改核心程式。

4.4 AI Integration

加入 Device Identification 後，將 Image Classification Service 整合進既有 Workflow。

使用既有 Inspection Image，透過 Xception Model 進行 Device Model Classification，再將結果提供給主要 Application。

Inference Service 使用 FastAPI 建立獨立 Service Interface，使 AI Model 與 Application Workflow 解耦。

4.5 Cloud & Customer Integration

完成核心 Grading Workflow 後，加入 Cloud Data Integration 與 Customer API。

平台逐步從單純的 Grading Application 擴展成涵蓋：

  • Inspection
  • AI Identification
  • Grading
  • Traceability
  • Cloud Integration
  • Customer Integration

的 Production Software Platform。

4.6 Production Deployment

產品進入 Production 後，持續處理：

  • Customer Acceptance
  • Grading Rule Tuning
  • Deployment
  • Architecture Documentation
  • Production Troubleshooting
  • Customer-specific Customization

並根據 Production Feedback 持續調整 System Architecture 與 Application Behavior。

05. 產品演進

5.1 從固定 Grading 到 Configurable Grading

第一階段先驗證基本 Grading Flow。

當 Customer Requirement 增加後，將原本 Hard-coded Grading Logic 演進成 Configurable Rule Engine。

使 Grading Logic 從單一產品邏輯，演進成可以支援不同 Grading Requirement 的平台能力。

5.2 從人工選擇到自動 Device Identification

原始流程需要 Operator 指定 Device Model。

加入 AI Device Identification 後，系統可以根據 Inspection Image 自動判斷 Device Model，再選擇對應 Configuration。

這降低人工介入，也讓後續 Inspection 與 Grading Workflow 可以根據 Device Model 自動使用對應設定。

5.3 從 Grading Application 到 Production Platform

產品最初只需要完成 Grade Calculation。

隨著 Production Requirement 增加，逐步加入：

  • Machine Integration
  • AI Identification
  • Configurable Grading
  • Production Traceability
  • Cloud Integration
  • Customer API
  • Reporting
  • Production Deployment

產品因此由單一 Grading Application 演進成完整 Production Platform。

5.4 Production-driven Iteration

整個產品不是一次完成所有功能，而是透過 Production Feedback 持續演進。

Production 使用過程中產生新的 Requirement、Integration Issue 或 Grading Rule 調整需求後，再回饋至 Architecture、Implementation 與 Deployment。

透過這種 Iterative Development，產品逐步從 MVP 演進成符合 Production 與 Customer Requirement 的 Software Platform。

06. 成果

6.1 產品成果

最終建立一套 Automated Smartphone Grading Platform，將既有 Inspection System 的結果接入後續 Production Workflow。

平台具備：

  • Automated Grading Decision
  • Configurable Grading Rules
  • AI-based Device Identification
  • Production Traceability
  • Cloud Data Integration
  • Customer API Integration
  • Production Reporting
  • Production Deployment

6.2 產品演進成果

產品由最初的 Basic Grading MVP，逐步演進為整合：

Inspection + AI + Grading + Traceability + Cloud Integration

的 Production Software Platform。

核心價值不只是自動產生 Grade，而是將 Inspection Result、Decision Logic、Production Data 與 External System Integration 組合成可持續演進的產品架構。

6.4 0 → 1 產品經驗

這個專案的核心經驗，是從既有 Inspection System 出發，將一個最初的 Grading MVP，逐步建立成能夠支援 AI、Configurable Decision Logic、Production Traceability、Cloud Integration 與 Customer Integration 的完整 Software Product。

這個過程涵蓋從 Product Definition、System Architecture、Software Development，到 Production Deployment 與後續 Product Evolution 的完整 0 → 1 開發流程。
