01. 工作背景

Firmware Development 是持續演進的過程，隨著新功能、Firmware Changes 與不同 Hardware Platforms 的支援持續增加，Validation Scope 也需要同步演進。

因此，需要持續建立與維護完整的 Firmware Validation & Automation，透過可重複執行的 Validation Tests 驗證 Firmware 的功能與行為，並在 Firmware 持續變更的過程中及早發現 Regression 與 Validation Failure。

我的主要工作即是在這個持續演進的開發流程中，負責 Firmware Validation & Automation，涵蓋從 Test Case Development、Manual Validation、Automation Implementation，到 Signoff Validation 以及 Failure Analysis & Resolution 的完整驗證流程。

在日常工作中，我同時處理 Manual Validation 與 Automation Validation，並針對不同 Hardware Validation Platforms，包括 SVP、VHS、ZEBU、HAPS 與 Silicon，進行 Firmware Behavior 驗證。

整體工作並不只是執行既有 Test Case，而是從 Test Requirement 開始，先確認 Validation Method，再建立 Test Procedure，透過 Manual Validation 確認測試邏輯與 Firmware Behavior，之後將穩定的 Test Procedure Automation，並持續透過 Signoff Validation 與 Failure Analysis 驗證 Firmware 品質。

因此，我的工作涵蓋 Test Development、Test Automation、Firmware Validation、Failure Analysis，以及 Validation Result Management。

02. 工作範疇

我的日常工作主要分為三個核心領域：

Test Case Development & Automation

負責將 Test Requirement 轉換成可執行且可重複驗證的 Test Case。

工作內容包含：

  • Test Requirement Analysis
  • Test Procedure Development
  • Manual Validation
  • Test Case Automation
  • Robot Framework / Python Implementation
  • CI/CD Pipeline Integration
  • Automation Code Review

Test Case Development 階段會先建立 PowerShell Test Procedure；確認測試流程與 Validation Criteria 後，再使用 Robot Framework / Python 實作 Automation Test Case。

Python Test Case 使用既有的 Firmware Command Library 實作 Firmware Commands，並整合至 CI/CD Pipeline 執行。

Signoff Validation

依照固定的 Signoff Schedule 執行 Firmware Signoff Validation，主要負責 SVP、VHS、ZEBU、HAPS 與 Silicon 等不同 Hardware Validation Platforms。

Validation 同時包含：

  • Automated Test Case
  • Manual Validation
  • Temporary Validation Request
  • 尚未完成 Automation 的 Test Case

完成驗證後，收集各 Platform 的 Validation Logs 與 Test Results，整理成 Signoff Report，提供給相關 Firmware Stakeholders。

Failure Analysis & Resolution

負責處理 Validation Failure，從 Failure Reproduction、Root Cause Analysis 到 Resolution Tracking。

分析時會從：

  • Validation Logs
  • Test Execution Flow
  • Command Results
  • Firmware Behavior
  • Repository Commit Difference
  • Firmware Version

等資訊確認 Failure 的發生原因，並判斷問題主要屬於 Test、Environment 或 Firmware。

在確認 Root Cause 後，也會進一步判斷問題是否屬於自己可以處理的範圍；若可以直接修正，則由自己進行修改與驗證，而不是將所有 Firmware-related Issues 直接交由其他 Firmware Stakeholder 處理。

03. 設計與實作

Test Case Development

當收到新的 Test Requirement 時，我會先與對應的 Requirement Owner / POC 確認需求，釐清：

  • Validation Function
  • Test Conditions
  • Expected Behavior
  • Validation Criteria
  • Platform Support

確認需求後，參考既有 Test Methods、Validation Documentation 與 Previous Test Procedures，建立對應的 PowerShell Test Procedure。

在進行 Automation 前，會先於指定 Hardware Platform 上手動執行 Test Procedure，確認：

  • Test Flow
  • Command Sequence
  • Firmware Behavior
  • Pass / Fail Criteria

並取得 Validation Logs 作為測試證據。

完成 Manual Validation 後，再將 Test Procedure 與 Validation Logs 交由相關 Stakeholder Review，確認測試內容、測試結果與 Validation Criteria 符合需求後，才進入 Automation Implementation。

這個流程先驗證 Test Logic 與實際 Firmware Behavior，再進行 Automation，降低將尚未驗證的 Test Flow 直接轉換成 Automation Test Case 的風險。

Automation Implementation

確認 PowerShell Test Procedure 後，將其轉換為 Robot Framework / Python Test Case。

Python Test Case 使用既有的 Firmware Command Library 實作 Firmware Commands，完成 Test Case 後整合至 CI/CD Pipeline 執行。

Automation 執行結果會搭配 Test Logs 進行確認，完成驗證後提交 Automation Code Review。

流程：

Test Requirement → Requirement / POC Confirmation → PowerShell Test Procedure → Manual Validation → Review → Robot Framework / Python Automation → CI/CD Pipeline → Result Validation → Code Review

Manual Validation

Manual Validation 主要用於確認新的 Test Procedure、臨時 Validation Request，以及尚未完成 Automation 的 Test Case。

實際操作時，會透過不同的 Remote Access 與 Firmware Communication Mechanisms 操作測試環境，執行 Firmware Commands，並確認 Firmware Driver 與 Firmware 之間的實際行為。

依照不同 Validation Scenario，測試可能透過：

  • Remote Shell / SSH
  • Command-line Test Tools
  • Firmware Communication Interface

等方式與 Firmware 進行互動。

Manual Validation 的目的不是單純執行 Command，而是確認 Test Procedure、Command Sequence 與實際 Firmware Behavior 是否一致，並取得後續 Automation 與 Failure Analysis 所需的 Validation Evidence。

Automation Execution

Automation Flow 由 CI/CD Pipeline 觸發 Test Agent 執行 Python / Robot Framework Test Case。

Automation Layer 依照 Test Case 執行 Firmware Commands，並透過既定的 Remote Communication Mechanisms 與 Test Environment 進行操作。

執行過程產生的 Logs 由 Automation Flow 收集並保存為 CI/CD Artifacts，供後續 Test Result Review 與 Failure Analysis 使用。

流程：

CI/CD Pipeline → Test Agent → Python / Robot Framework → Remote Communication → Test Environment → Firmware

透過將 Automation 與 CI/CD Pipeline 整合，Validation Test 可以在一致的執行環境中重複執行，並保留對應的 Test Result 與 Log Evidence。

Signoff Validation

團隊依照固定週期執行 Signoff Validation，我主要負責 SVP、VHS、ZEBU、HAPS 與 Silicon 的驗證。

Automated Validation 會直接使用既有 Automation Test Case 執行；Manual Validation 則用於臨時性的驗證需求，以及尚未完成 Automation 的 Test Case。

對於臨時性的 Validation Request，我會先與 Requirement Owner / POC 確認 Validation Method，再依照確認後的流程執行。

對於尚未 Automation 的 Test Case，則使用 Test Case Development 階段建立並驗證過的 PowerShell Script 執行。

完成 Signoff 後，收集各 Platform 的 Validation Logs 與 Test Results，整理成 Signoff Report。

如果 Signoff 過程發現 Failure，則將相關項目建立至 Issue Tracking System，進入後續 Failure Analysis 與 Resolution Tracking。

Failure Analysis & Resolution

當 Customer、QA 或其他 Validation Stakeholder 發現 Test Failure 時，收到 Failure Report 後，我會先確認 Failure 的 Occurrence Frequency 與 Criticality，再安排後續處理優先順序。

對於需要優先處理的 Failure，首先透過 CI/CD Pipeline 嘗試重現問題。

如果 Automation Flow 無法重現，則進一步透過 Manual Test 驗證，以區分問題是否與 Automation Flow 有關。

成功重現後，開始定位 Failure 發生的位置，並分析：

  • Validation Logs
  • Test Execution Flow
  • Command Results
  • Firmware Behavior
  • Repository Commit Difference
  • Firmware Version

必要時會 Checkout 舊版本並重新執行 Manual Test，透過 Version / Commit Difference 確認問題是否與特定版本或 Code Change 相關。

完成 Root Cause Analysis 後，依據問題類型判斷後續處理方式。

如果問題來自 Test 或 Automation，則修正對應的 Test Case、Test Flow 或 Automation Implementation。

如果問題確認與 Firmware 有關，也會先進一步分析問題是否屬於目前負責範圍，以及是否可以由自己直接修正。

若確認可以處理，則直接進行 Firmware Code 修改，完成修正後重新執行 Validation，確認 Fix 是否有效。

若問題需要其他 Firmware Stakeholder 進一步處理，則整理完整的 Failure Evidence，包括 Validation Logs、Reproduction Result、Version Difference 與 Root Cause Analysis，提供後續 Firmware Resolution。

整體處理流程：

Test Failure → Frequency / Criticality Analysis → Failure Reproduction → Automation / Manual Test → Root Cause Analysis → Test / Environment / Firmware → Self-Fix / Issue Escalation → Re-Validation → Resolution

這個流程除了確認問題來源，也保留從 Failure Analysis 到實際修正與重新驗證的完整閉環。

04. 持續改善

除了執行既有 Validation，我也會持續將已驗證的 Manual Test Procedure 轉換成 Automation Test Case。

循環：

Manual Validation → Test Procedure Verification → Automation → CI/CD Execution → Signoff Validation → Failure Analysis → Test / Automation Improvement

透過先 Manual Validation、再 Automation 的方式，可以在 Automation 前先確認 Test Logic、Command Sequence 與 Firmware Behavior，降低將錯誤 Test Flow Automation 化的風險。

同時，將完成驗證的 Test Case 整合至 CI/CD Pipeline，使原本需要人工執行的 Validation 可以逐步轉換為可重複執行的 Automated Test。

在 Failure Analysis 過程中，也會根據 Failure Evidence、Version Difference 與實際 Firmware Behavior 持續檢視 Test Flow。

當發現問題來自 Test 或 Automation 時，會修正對應的 Test Case 或 Automation Flow。

當問題來自 Firmware 時，也會先判斷是否屬於自己可以處理的範圍。若可以修正，則直接進行 Firmware Code Modification、Validation 與 Fix；若需要其他 Firmware Stakeholder 進一步處理，則提供完整 Failure Evidence 支援後續 Resolution。

因此，Validation 不只是一次性的測試活動，而是透過 Automation、Signoff、Failure Analysis 與 Fix Validation 持續回饋 Test Coverage、Automation Flow 與 Firmware Quality。

最終形成：

Test Development → Manual Validation → Automation → CI/CD → Signoff → Failure Analysis → Fix → Re-Validation

的持續驗證循環。

05. 產出與影響

Reusable Firmware Validation Tests

將經過 Manual Validation 與 Review 的 Test Procedure 轉換成 Robot Framework / Python Automation Test Case，建立可重複執行的 Firmware Validation Tests。

CI/CD Validation

將 Automation Test Case 整合至 CI/CD Pipeline，使 Firmware Validation 可以納入自動化執行，並將執行結果與 Logs 保存為 CI/CD Artifacts。

Multi-Platform Validation

支援 SVP、VHS、ZEBU、HAPS 與 Silicon 等不同 Hardware Validation Platforms 的 Firmware Validation，確保 Test Case 能夠涵蓋不同 Validation Environments。

Signoff Validation

持續執行不同 Hardware Validation Platform 的 Signoff Validation，並將 Validation Logs 與 Test Results 整理成 Signoff Report，作為 Firmware Signoff 的驗證資料。

Failure Evidence & Resolution

針對 Validation Failure 建立從 Failure Reproduction、Root Cause Analysis 到 Resolution Tracking 的完整處理流程。

當問題可以由自己處理時，會直接進行 Test、Automation 或 Firmware 修正，並透過 Re-Validation 確認修正結果。

當問題需要其他 Stakeholder 進一步處理時，則整理完整 Failure Evidence，支援後續 Resolution。

主要產出：

  • Firmware Fix PR
  • Test / Automation Fix
  • Failure Evidence
  • Failure Analysis Report
  • Validation Logs
  • Signoff Report

這些資料支援後續 Firmware Modification、Validation 與 Failure Tracking。

Validation Flow 持續演進

透過：

Test Development → Manual Validation → Automation → CI/CD → Signoff → Failure Analysis → Fix → Re-Validation

建立完整的 Firmware Validation Engineering Flow。

在這個循環中，Manual Validation 用於確認 Test Logic 與 Firmware Behavior，Automation 提供可重複執行的驗證能力，CI/CD 提供一致的執行環境，而 Failure Analysis 則將實際問題回饋至 Test Development、Automation 與 Firmware Development。

對於可以由自己處理的問題，直接完成修正與驗證；對於需要其他 Stakeholder 處理的問題，則透過完整 Failure Evidence 支援後續 Resolution。

最終形成一個可以持續累積 Test Coverage、Automation Capability、Failure Knowledge 與 Firmware Validation Experience 的 Firmware Validation Workflow。
