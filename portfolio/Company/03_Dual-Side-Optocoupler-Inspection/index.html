01. 專案背景

本專案主要用於檢測具有非平滑表面的光耦合器之外觀瑕疵，包括異色、裂紋、Dent、缺件與刮傷。

由於產線需要處理大量料片，若依靠人工逐顆進行目視檢查，整體檢查時間較長，也需要投入較多人工。此外，隨著人員變動，還需要持續培訓新的檢查人員，增加人力與培訓成本。

部分外觀瑕疵也涉及人工判斷，因此不同人員之間可能存在判斷差異。基於檢查效率與檢測一致性的需求，導入 AOI（Automated Optical Inspection）將人工目視檢查轉換為自動化影像檢測。

由於光耦合器具有上下兩個對稱表面，兩個表面皆需要進行外觀檢測，因此本專案除了 AOI 軟體與影像檢測外，也基於既有檢測機台架構新增下罩檢查模組，使單一設備具備上、下表面檢查能力，完成完整的雙面檢測流程。

02. 專案目標與系統架構

2.1 專案目標

本專案的主要目標，是將原本的人工外觀檢查轉換為自動化 AOI 檢測，提升檢查效率與檢測結果的一致性。

同時，基於既有機台架構新增下罩檢查，使單一設備具備上、下表面檢查能力，並建立從 AOI Inspection、Inspection Review 到 Defect Removal 的完整前後站流程。

2.2 系統架構

整體系統由 Loader、AOI、Unloader、Inspection Review Station 與 Defect Removal Machine 組成。

Loader 提供待檢測料片的識別資訊，AOI 取得資訊後執行對應的 Inspection Workflow。

AOI 完成檢測後，Unloader 會主動提供目前需要處理的 Cast Number 與 Index。AOI 取得並確認對應資訊後，才執行後續出料流程。

AOI 同時負責將檢測流程所需的完整資料傳送至 Inspection Review Station，Review 依據 AOI 提供的資料進行人工確認。

Review 確認後的結果再提供給 Defect Removal Machine，作為後續瑕疵元件移除的依據。

透過前後站的整合，將 Material Handling → Dual-Side AOI Inspection → Inspection Review → Defect Removal 串接成完整的自動化檢測流程。

03. 我的設計與實作

3.1 AOI System Integration

本專案涉及多個 Vendor 設備，因此 AOI 並不是單獨執行檢測，而是需要與前後站設備建立穩定的工作流程整合。

在開發過程中，我與 Vendor 共同定義設備之間的通訊規格，並負責 AOI 端的通訊實作，將設備間的資料交換與狀態確認整合至 AOI Workflow。

AOI 根據 Loader 提供的 Cast Number 與 Index 開始啟動入料流程然後執行 Inspection Workflow。完成檢測後，Unloader 會主動提供目前需要處理的 Cast Number 與 Index，AOI 取得並確認資訊後，再執行後續出料流程。

同時，AOI 將檢測流程所需的完整資料傳送至 Inspection Review Station，供後續人工確認。

除了軟體實作，我也透過實際設備測試確認 Vendor Equipment 的動作符合雙方定義的規格，確保軟體流程與設備行為一致。

3.2 CNN-based Crack Inspection

針對光耦合器表面的裂紋瑕疵，我負責 CNN-based Crack Inspection 的完整設計與實作。

原有的 Rule-based Image Processing 在面對非平滑表面的細微、不規則裂紋與刮傷時，較難建立穩定的判定規則。此外，裂紋與刮傷在影像中的外觀特徵較為相近，若僅依靠傳統影像處理規則進行判斷，容易產生漏檢。

因此，本專案導入 CNN，透過模型學習影像中的缺陷特徵，提升對複雜外觀缺陷的辨識能力。

我負責從資料建立到模型部署的完整流程，包括影像資料收集、資料分類、Training / Testing、模型評估、Retraining，以及最終模型整合至 AOI Inspection Pipeline。

本專案將資料分為 Crack 與 OK 兩類，並透過持續收集實際檢測影像進行 Model Retraining，使模型能夠隨著資料累積持續改善。

經過模型評估後，選擇當時驗證結果較佳的 Xception 作為最終模型，並將其整合至 AOI Inspection Workflow。

3.3 Inspection Strategy & Classification Policy

在 CNN Crack Inspection 的設計中，我除了負責模型訓練與整合，也根據實際產品的缺陷分布設計 Inspection Strategy。

經過實際檢測影像觀察後，發現 Crack 大多出現在元件的四個角落，因此不需要將整個元件影像直接交給 CNN 進行判定。

因此，我將檢測區域限制在元件的四個特定角落，分別建立對應的 ROI（Region of Interest），讓 CNN 只針對可能出現 Crack 的區域進行特徵判斷。

在 Dataset 建立上，模型分類定義為 Crack / Non-Crack。其中 Crack 為目標缺陷，其餘不屬於 Crack 的影像則歸類為 Non-Crack，包含 Scratch。

透過限制 ROI，可以讓模型集中學習實際 Crack 可能出現區域的影像特徵，同時降低其他非檢測區域對模型判定的干擾。

最終，四個 ROI 的檢測結果再整合至 AOI Inspection Workflow，作為後續 Crack Inspection 的判定依據。

3.4 HALCON-based Scratch Inspection Integration

原有 AOI 系統需要增加 Scratch Inspection，但同時希望維持既有 C++ 軟體架構，並讓 FAE 能夠透過 AOI Software UI 調整檢測設定。

因此，我選擇將 HALCON C++ Library 整合至既有 AOI 環境，而不是建立獨立的 Scratch Inspection 工具。

為了避免 HALCON 功能影響沒有使用該功能的既有流程，我將其設計為可選擇啟用的功能模組。Software Startup 時決定是否啟用 HALCON；未啟用時，相關 UI 選項同步關閉。

啟用後，FAE 可以透過 AOI Software UI 設定檢測區域與相關參數。實際 Scratch Inspection 則使用 HALCON 的 Line Gauss 方法進行檢測，取得結果後再交由既有 Inspection Workflow 進行後續判定。

透過這樣的整合，Scratch Inspection 成為既有 Inspection Framework 中的一個可選功能，而不需要建立獨立的檢測工具。

3.5 Inspection Review Station

AOI 完成檢測後，檢測結果需要進一步透過 Inspection Review Station 進行人工確認，因此我負責 Review 流程相關的軟體整合與 UI 修改。

Review Station 接收 AOI 提供的檢測資料，讓操作人員可以根據 AOI 的檢測結果進行人工確認。

我負責將 AOI 檢測資訊與 Review Station 的操作流程串接，使 AOI 的檢測結果能夠進入後續人工確認流程。

此外，Review 過程中的實際檢測影像也具有後續 AI Model Development 的價值，因此將部分non-Crack與所有Crack影像納入資料收集流程，作為後續 Dataset 建立與模型 Retraining 的來源。

因此，Inspection Review 不只是人工確認流程，也成為 Production Data 回饋至 AI Development 的重要節點。

3.6 Offline AI Retraining Workflow

CNN 模型導入生產環境後，實際檢測過程仍會持續產生新的影像資料，因此我進一步建立 Offline AI Retraining Workflow，讓生產資料能夠回饋至模型開發流程。

實際檢測影像經過收集與 Dataset Preparation 後，在 Offline Environment 進行 Training 與 Model Evaluation，再將符合需求的模型重新整合至 AOI Inspection Workflow。

模型訓練與生產檢測流程彼此分離，避免模型開發過程直接影響線上 AOI Inspection。

當累積新的有效資料後，可以透過 Offline Retraining 重新訓練模型，完成評估後再將更新後的模型導入 AOI。

如此一來，AI Inspection 從一次性的 Model Development，轉變為可以持續累積資料、重新訓練、評估與更新的流程。

3.7 Machine Modification — Dual-Side Inspection

原有檢測機台無法直接完成產品上下兩個表面的完整檢查，因此除了 AOI Software 與 Image Inspection 外，我也參與既有機台的功能擴充。

基於既有檢測機台架構，新增下罩檢查模組，使單一設備具備上、下表面檢查能力，完成完整的雙面檢測流程。

上下表面的檢測使用相同的檢測模組，但在實際掃描時，需要考量兩個模組同時進行光源照射可能互相影響成像結果。因此，在自動化路徑規劃時，需要避免上下兩個模組處於垂直對應的位置，降低另一側光源對當前影像擷取造成的干擾。

因此，除了新增下表面檢測能力外，我也需要將 Machine Motion、Scan Path Planning、Image Acquisition 與 AOI Inspection Workflow 整合，使設備能夠依照規劃的路徑完成上下表面的檢測，同時維持影像品質。

透過機台動作與檢測流程的整合，最終使同一套設備能夠完成產品兩個表面的自動化檢測。

04. 成果

本專案將原本依賴人工的外觀檢查流程轉換為自動化 AOI Inspection，並將 Machine、Software、Computer Vision、Deep Learning 與 Production Workflow 整合至同一套檢測系統。

在檢測能力上，系統能夠針對異色、裂紋、Dent、缺件與刮傷進行自動化檢測，並透過 CNN-based Crack Inspection 與 HALCON-based Scratch Inspection 處理不同類型的外觀瑕疵。

在設備能力上，基於既有機台架構新增下罩檢查，使單一設備具備上、下表面檢查能力，完成雙面檢測。

在 Production Workflow 上，則將 Material Handling → AOI Inspection → Inspection Review → Defect Removal 串接起來，使檢測結果能夠進入後續人工確認與瑕疵移除流程。

同時，透過 Inspection Review 收集實際生產影像，再進入 Offline AI Retraining Workflow，使 Production Data 能夠持續回饋至模型開發與更新。

最終，本專案不只是完成一套 AOI Inspection Function，而是建立從 自動化檢測、設備整合、人工確認、資料收集到 AI 持續改善 的完整工程流程，將原本的人工檢查需求轉換為可實際運作並持續演進的自動化檢測系統。
