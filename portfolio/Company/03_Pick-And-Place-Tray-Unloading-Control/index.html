01. 專案背景

Wafer 生產過程中，Pick & Place Equipment 需要依據不同產品使用對應的 Tray Configuration。

不同產品可能使用不同的 Tray Type，而不同 Tray 又具有不同的 Slot Layout、Placement Rules 與 Capacity。因此，在開始生產前，需要根據實際的 Production Work Order 準備正確的 Tray Configuration。

原有流程需要由 Operator 依據 Work Order 與產品需求進行設定。當產品與 Tray Configuration 增加後，人工判斷與設定容易產生錯誤，也增加生產前的操作負擔。

因此，本專案建立一套 Production Software，將 Work Order Information 與 Tray Configuration 建立關聯，讓 Operator 掃描 Work Order 後，由系統自動產生對應的 Pick & Place Configuration。

本專案的主要工程問題為：

如何讓 Work Order 成為機台 Configuration 的來源，將原本依賴人工判斷的 Tray 設定流程轉換成自動化流程？

我主要負責 C# Production Application 的設計與實作，以及 Work Order、Tray Configuration 與 Pick & Place Equipment 之間的流程整合。

02. 專案目標與系統架構

2.1 專案目標

本專案的主要目標，是建立 Work Order-driven Configuration Workflow，讓 Production Software 根據 Work Order 自動準備 Pick & Place Equipment 所需的設定。

整體流程包含：

  1. Operator 掃描 Production Work Order
  2. Application 取得 Work Order Information
  3. 根據產品需求判斷對應的 Tray Type
  4. 載入對應的 Tray Configuration
  5. 產生 Machine Configuration
  6. 將 Configuration 交付 Pick & Place Equipment
  7. 由設備依據 Configuration 執行 Placement Operation

核心概念為：

Work Order → Configuration Decision → Machine Configuration → Pick & Place

2.2 System Architecture

整體系統以 C# Production Application 作為 Production Workflow 與 Pick & Place Equipment 之間的 Configuration Layer。

Operator 只需要從 Production Work Order 開始操作，Application 負責取得 Work Order Information、進行 Configuration Decision，並產生設備所需的 Machine Configuration。

完成 Configuration Generation 後，Application 再透過既定的 Configuration Exchange Mechanism 將設定交付至 Pick & Place Equipment，由設備執行後續的 Placement Operation。

透過這樣的架構，Operator 不需要直接處理底層 Machine Configuration，而是由 Production Software 將產品需求轉換為設備可以使用的 Configuration。

03. 我的設計與實作

3.1 Work Order Processing

我使用 C# 開發 Production Application，建立 Work Order-driven 的 Configuration Workflow。

Operator 開始生產前掃描 Production Work Order，Application 取得 Work Order Information 後，進一步判斷目前生產所需要的 Tray Configuration。

將 Work Order 作為 Configuration Source，可以將原本由 Operator 進行的 Configuration Decision 移至 Software Workflow。

因此，Operator 不需要自行判斷應該使用哪一種 Tray Configuration，而是由 Application 根據 Work Order 執行對應的設定流程。

3.2 Tray Configuration Logic

不同 Tray Type 具有不同的 Slot Layout、Placement Rules 與 Capacity，因此系統需要根據 Work Order 對應到正確的 Tray Configuration。

我負責建立 Configuration Logic，將：

Work Order Information → Tray Type → Tray Configuration

串接起來。

完成 Tray Configuration 後，再將相關設定轉換為 Pick & Place Equipment 可以使用的 Machine Configuration。

透過將產品需求與機台設定分離，使 Application 可以負責 Configuration Decision，而設備則專注於執行對應的 Placement Operation。

3.3 Machine Configuration Integration

完成 Configuration Generation 後，Application 透過既定的 Configuration Exchange Mechanism 將 Machine Configuration 交付至 Pick & Place Equipment。

Pick & Place Equipment 取得對應設定後，依據 Configuration 執行後續的 Placement Operation。

因此，Production Software 不需要直接處理設備內部的控制細節，而是負責將 Production Information 轉換為 Machine Configuration，完成 Software 與 Equipment 之間的整合。

實際的 Machine Configuration Format、設備內部控制規則與其他內部實作細節不在公開 Portfolio 中呈現。

3.4 Production Workflow Integration

除了 Configuration Generation，我也將設定流程整合至實際 Production Workflow。

Operator 的操作流程被簡化為：

Scan Work Order → Generate Configuration → Prepare Machine

Application 負責處理中間的 Configuration Decision 與 Machine Configuration Generation。

因此，Production Software 不只是單純的 Configuration Generator，而是成為 Work Order 與 Pick & Place Equipment 之間的 Production Integration Layer。

3.5 Configuration Consistency

本專案主要需要處理不同產品與 Tray Configuration 之間的對應關係。

當不同產品需要不同 Tray Configuration 時，如果將判斷責任留在 Operator，流程容易受到人工選擇與設定影響。

因此，我將 Configuration Decision 從人工操作移至 Software Workflow，使系統根據 Work Order 自動決定所需設定。

透過這種方式，Production Requirement 可以透過一致的 Software Logic 轉換成 Machine Configuration，降低人工設定對生產流程造成的影響。

04. 成果

本專案建立 Work Order-driven Pick & Place Configuration Workflow，將原本需要人工判斷與設定的 Tray Configuration 流程轉換為由 Software 驅動的自動化流程。

Production Software 可以根據 Work Order 自動對應 Tray Type 與相關 Configuration，並產生 Pick & Place Equipment 所需的 Machine Configuration。

同時，透過 Production Software 與 Equipment 之間的 Configuration Integration，使 Machine Configuration 能夠從 Production Workflow 自動產生並交付設備使用。

Operator 不需要直接處理底層 Machine Configuration，而是從 Work Order 開始，由系統負責後續的 Configuration Preparation。

最終將 Work Order、Tray Configuration 與 Pick & Place Equipment 串接成完整的 Production Configuration Workflow，將原本依賴人工判斷的設定流程轉換為 Work Order-driven、Software-controlled 的生產流程。
